# Статус поставки

Дата: 26 сентября 2026. Эта запись отличает готовые локальные материалы от удалённой публикации и будущей реализации.

## Подготовлено локально

- Игровой дизайн по презентации и интервью, архитектура с источниками, roadmap с критериями перехода.
- OpenSpec `design-gnom-fiji-racing`: proposal, design, четыре capability-спецификации и tasks. Строгая валидация прошла.
- Технический прототип Godot 4.7.2: Web-клиент, headless worker, тестовая трасса и машина, дрифт/ускорение, HTML-оболочка и PostgreSQL backend с local/test входом.
- Десять SVG-листов: восемь основных экранов, схема архитектуры и ключевые состояния интерфейса; PNG-превью и галерея. Игровое окружение и машина являются сгенерированным концепт-артом, не скриншотами работающего Godot-прототипа.

## Проверено

Официальная portable-сборка `4.7.2.stable.official.ed1daf0bf` выполняет import и Web export с templates, проверенными по SHA-256. Выполнен также Linux ARM64 cross-export; запуск на Linux ARM не проверен. При sandboxed export на macOS возникала диагностическая строка чтения системного хранилища CA; export завершился с кодом 0, GDScript-ошибок не было. Сертификаты и системная защита не изменялись.

Проверки технического прототипа:

- Vehicle probe: 33 assertions, включая дрифт/ускорение, прыжок, отдельную локальную гравитацию и выход из лобового упора в барьер.
- Track probe: 29 assertions; protocol/lap/standings probe: 64; client reconciliation probe: 12; реальный socket resume probe: 5. Последний проверяет уже накопленный пакет после 7-секундной паузы, до timeout на первом physics tick.
- WebSocket integration: 29 проверок с реальным headless worker, включая билеты, replay, лимиты, input timeout и переподключение.
- Backend: 22/22 теста (11 auth и 11 lifecycle), включая настоящий PostgreSQL 18.4, отмену старта/SQL/initdb и ошибки конфигурации. Отдельный HTTP smoke входа/отзыва сессии, TypeScript и build прошли. Тестовые кластеры удаляются после остановки. `npm audit` всех зависимостей: 0 уязвимостей на дату проверки.
- Chromium: два изолированных dev-аккаунта в одной серверной гонке, управление после окна профиля, меню/возврат на трассу/выход/повторный вход, серверное торможение при приостановке вкладки, непустой и изменяющийся при движении 3D canvas. Финальный прогон: заряд 0.312, ускорение 0.927 секунды, возврат замороженной вкладки без разрыва соединения и с тем же player ID.
- Отдельный браузерный прогон: явное подтверждение переноса гостя через настоящий API, Escape/продолжение, выход из аккаунта; HUD в 1600x900, 390x844, 844x390 и 568x320. Контролируемая UI-fixture из 10 участников оставляет видимым текущего игрока на 10-м месте; пересечений панелей нет. Это проверка компоновки, не десять реальных браузеров. Ошибок JavaScript в успешных финальных прогонах нет. Browser plugin отсутствовал, использован Playwright и отдельный визуальный просмотр во встроенном браузере.
- ARM-стенд: 3 unit-теста probe и 5 тестов выбора локального Docker endpoint, синтаксис JS/TS, YAML и отказ запуска на неподдерживаемой платформе. Docker и Linux ARM runtime здесь не запускались.
- Генератор ARM-стенда прошёл отдельный 15-секундный smoke на macOS/local: 10 настоящих гостевых API-сессий и socket-клиентов, движение и snapshots у каждого, ошибок нет. Это не ARM-тест и не 10 браузеров.

Проверки функциональные, не нагрузочные. Конкурирующие headless WebGL-сессии работали около 4 FPS; финальные headed Chromium прогоны показывали 60 FPS. Один расширенный прогон остановился по таймауту ожидания скорости; повтор с диагностикой прошёл, устойчивый performance budget этим не подтверждён. Эти короткие наблюдения не доказывают производительность сервера на 4/8 ядрах. Реконсиляция проверена на локальном протоколе; сетевые потери/задержки и выбор WebRTC/WSS остаются отдельным этапом 2.5.

На текущем хосте чтение исполняемых файлов из Documents приводило к задержкам и SIGKILL нативного PostgreSQL. Та же проверенная npm-поставка в материализованном временном каталоге прошла тесты за 1.1 секунды. Для рабочего локального запуска использована копия build/backend/game/web в `/private/tmp/gnom-live-prototype` и `PG_BIN_DIR=/private/tmp/gnom-postgres-runtime/native/bin`. Подписи и Gatekeeper не отключались. Это копия сборки, не hot reload исходников; процедура описана в [backend README](../backend/README.md). Временная локальная БД не содержит реальных пользовательских или платёжных данных.

Адрес текущего стенда: `http://127.0.0.1:8787`. Остановка именно этой временной копии: `node /private/tmp/gnom-live-prototype/scripts/dev.mjs --stop`. Каталог `/private/tmp` не является постоянным местом хранения проекта; исходники и воспроизводимые команды остаются в репозитории.

Dev launcher рассчитан на последовательный запуск и остановку. Не запускать две команды `--detach` одновременно: single-instance проверка пока не защищена атомарным lock; для production этот launcher не предназначен.

Финальную проверку прервал disk-full на macOS: iCloud выгрузил рабочие файлы и Git-метаданные. Удалены только созданные этой работой ненужные загрузочные архивы и остановленные тестовые БД, затем папка проекта восстановлена через Finder Download Now без изменения настроек iCloud. После восстановления повторены backend tests/typecheck/build и проверка templates; изменения Git сохранились. Для дальнейшей разработки стоит избегать выгружаемого iCloud checkout.

SVG отрендерены и визуально проверены. Playwright подтвердил отсутствие выхода текста за холст на всех десяти листах, загрузку изображений галереи и отсутствие горизонтального переполнения галереи при 390 px. Это не тест мобильного игрового интерфейса. Демонстрационные цены, рейтинг и характеристики не являются утверждёнными настройками игры. Итоговый список файлов и проверка текста находятся в `design/README.md`.

## Границы прототипа

Макеты приняты пользователем 2026-09-26; запись проверки с ID листов находится в `design/figma-publication.json`. Figma остаётся визуальным baseline. Хаб использует принятый концепт-арт; палитра, типографика и расположение HUD перенесены в браузерную оболочку. Игровой мир пока является тестовой геометрией, а не производственным 3D-контентом из концепта. Вместо неработающих магазина/инвентаря/предметов показываются только доступные элементы технического заезда. В HUD отображаются реальные участники, состояние связи, круг, время, скорость и заряд.

Google-вход, предметы, боты, столкновения машин друг с другом, рейтинг, кампания, магазин и награды гонки ещё не реализованы. Dev-вход доступен только local/test с отдельной БД и явным флагом; production и public staging с таким флагом завершают запуск ошибкой. Уже выданный race ticket живёт до 60 секунд и не отзывается онлайн при logout; это ограничение прототипа, не production-контракт готовой авторизации.

Пользователь выбрал подготовку ARM-стенда без аренды. [Runbook](arm-test-stand.md) и Compose сохранены, но задача 2.7 остаётся открытой: нет проверенного Linux ARM-хоста, TURN и измерений physics p99/RSS/CPU/стоимости. Следующий технический gate: сравнение WebRTC/native extension/TURN и WSS при потерях/задержках. Дальнейшие игровые этапы остаются в OpenSpec tasks; весь change не завершён и не архивирован.

В OpenSpec закрыто 14 из 60 задач, включая 2.1–2.4, 2.6 и 2.8 технического прототипа. Адаптивная компоновка не заменяет будущий touch adapter и проверку игры на реальных телефонах.
