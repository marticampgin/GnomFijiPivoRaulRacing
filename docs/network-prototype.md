# Локальный сетевой прототип

Статус: технический Godot/WebSocket-проход для задачи 2.4. Это не публичный ranked-сервис и не подтверждение выбора production-транспорта в задаче 2.5.

## Контракт

- Один Godot headless worker слушает только `127.0.0.1:9080`; `RACE_PORT` позволяет выбрать другой локальный порт.
- `RACE_TICKET_SECRET` должен содержать не менее 32 символов и совпадать с секретом API. В браузер этот секрет не передаётся.
- API выдаёт краткоживущий билет для `prototype-1`: `base64url(JSON).base64url(HMAC-SHA256)`. Worker проверяет подпись, срок, версию протокола, матч, loadout и одноразовый `jti`.
- До авторизации разрешён только `join`. Идентификатор и имя игрока берутся из подписанного билета, а не из произвольного пакета клиента.
- Максимум 10 машин, включая места отключившихся игроков в течение 30 секунд. Новый билет для прежнего игрока переподключает его к сохранённой позиции; старое соединение заменяется.
- Физика считается на сервере с частотой 60 Гц, снимки рассылаются с частотой 20 Гц. Клиент передаёт только конечные, ограниченные по диапазону значения input и возрастающий sequence.
- Сервер обрабатывает не более одной команды на физический тик. Через 250 мс без input либо при disconnect включает тормоз. Ограничены размер пакета, частота, очередь ввода, число соединений и исходящий backlog.
- Неавторизованное соединение живёт максимум 5 секунд. При закрытии transport принудительно освобождает TCP-соединение через секунду, даже если клиент не отвечает на close handshake.

## Клиент

Локальная машина предсказывает движение тем же контроллером. Входящий snapshot буферизуется; authoritative state восстанавливается в начале физического тика, затем непризнанные команды повторяются с фиксированным шагом. Replay не выполняется из render/process callback, поскольку `CharacterBody3D.move_and_slide()` использует контекстный delta движка. Очередь ограничена 120 командами, старые snapshots отбрасываются. Пропажа снимков или переполнение очереди приводит к отключению, а не бесконечной неподтверждённой симуляции.

Остальные машины интерполируются с буфером 100 мс. Коллизии между машинами пока отключены симметрично на сервере и клиенте: их согласование и поведение под задержкой требуют отдельного шага. Стены и дорожное покрытие имеют одинаковые коллизии в обоих процессах.

DOM-оболочка регистрируется через `GnomHost.register(callback)` и получает JSON через `GnomHost.update(json)`. Callback принимает JSON-сообщения `join`, `leave`, `focus`, `input_enabled`, `recover`, `restart`. HUD содержит измеренные скорость, дрифт, boost, круг, время, список игроков, world position, ping, correction distance и размер pending queue. Эти показания не являются доверенным результатом заезда.

## Прогресс гонки

Worker начинает с трёхсекундного отсчёта. Круг засчитывается после последовательного прохождения 16 секторов. Первое пересечение стартовой линии не завершает круг; финиш требует трёх полных кругов. Восстановление машины выполняет сервер у последней контрольной точки. `restart` сбрасывает только тренировочный прогресс этой машины.

В этой локальной проверке можно войти после старта и перезапустить собственную попытку. Общая lobby ready-state, публичный подбор, боты, предметы, столкновения машин, рейтинговые результаты и запись наград не реализованы. Никакие деньги, инвентарь или рейтинг worker не изменяет.

## Проверка

```sh
"$GODOT_BIN" --headless --path game --script res://tests/network_protocol_probe.gd
"$GODOT_BIN" --headless --path game --script res://tests/network_client_probe.gd
node scripts/test-network.mjs
```

`GODOT_BIN` указывает на зафиксированный Godot 4.7.2. Интеграционный тест сам запускает временный worker на `127.0.0.1:19080` с тестовым ключом и завершает его; `NETWORK_TEST_PORT` переопределяет порт. Требуется разрешённый loopback networking.

Подтверждено: 64 проверки протокола, контрольных точек и порядка машин, 10 проверок буферизации и physics-tick reconciliation клиента, 29 проверок реальных WebSocket-соединений. Интеграция покрывает два клиента, движение от input, остановку при потере input, сохранение позиции при переподключении, подпись/срок/повтор билета, повтор sequence, неверный input, неизвестные пакеты, rate limit и лимит 10 мест.

Это функциональные проверки на текущем компьютере, не нагрузочный профиль ARM-сервера. Задержка, потеря пакетов, production TLS/WSS, WebRTC/TURN и число параллельных гонок ещё не измерены. Нынешний WebSocket transport нужен для воспроизводимого локального прототипа; его head-of-line blocking остаётся открытым риском для production.
